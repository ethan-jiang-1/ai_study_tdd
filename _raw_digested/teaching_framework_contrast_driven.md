## 2小时PPT教学大纲

## 教学目标与受众分析

**目标受众**：
- 各层级的开发者（新手到资深）
- 感性认知较强，更容易被故事和情感打动
- 需要激发学习动力和紧迫感
- 喜欢通过对比和案例理解抽象概念

**核心教学目标**：
- 通过强烈对比激发学员的学习动力
- 让学员在故事中看到自己，产生认同感
- 展示AI+TDD的具体价值和实践方法
- 提供明确的成长路径和避坑指南

**教学特色**：
- 故事性强，易于记忆和传播
- 情感冲击力大，激发行动力
- 对比鲜明，说服力强
- 实用性强，立即可行

**幻灯片1：时间线**

### 秘密2：测试先行的威力（15分钟）

**幻灯片25-26：同一需求，不同处理**
**需求**：用户登录功能（带防暴力破解）

**小明的处理方式**：
```
1. 直接提问：帮我写个带防暴力破解的登录功能
2. AI输出代码
3. 简单测试：输入正确密码，能登录成功 ✓
4. 上线
```

**小华的处理方式**：
```
1. 先设计测试场景：
   - 正确密码应该登录成功
   - 错误密码应该返回失败信息
   - 连续5次错误应该锁定账户
   - 锁定期间正确密码也不能登录
   - 锁定时间过后应该可以重新尝试
2. 与AI对话实现
3. 运行所有测试确保完整性
```

**幻�灯片27-28：现场代码对比**

**小明版本（AI直接生成）**：
```javascript
function login(username, password) {
  const user = database.findUser(username);
  if (user && user.password === password) {
    return { success: true, user: user };
  }
  // 简单的失败计数
  user.failCount = (user.failCount || 0) + 1;
  if (user.failCount >= 5) {
    user.locked = true;
  }
  return { success: false, message: "登录失败" };
}
```

**问题分析**：
- ❌ 密码明文比较
- ❌ 没有锁定时间概念
- ❌ 成功登录后没有重置失败计数
- ❌ 没有考虑并发情况

**小华版本（测试驱动）**：
```javascript
// 先有测试用例
describe('用户登录', () => {
  test('正确密码应该登录成功且重置失败计数', () => {
    // Given
    const user = { username: 'test', password: hashedPassword, failCount: 3 };
    
    // When
    const result = login('test', 'correctPassword');
    
    // Then
    expect(result.success).toBe(true);
    expect(user.failCount).toBe(0); // 成功后重置
  });
  
  test('连续5次失败应锁定30分钟', () => {
    // 具体测试逻辑...
  });
});

// AI基于测试生成的实现
function login(username, password) {
  const user = database.findUser(username);
  
  // 检查是否被锁定
  if (user.lockedUntil && user.lockedUntil > new Date()) {
    return { success: false, message: "账户已锁定" };
  }
  
  // 验证密码
  if (bcrypt.compare(password, user.hashedPassword)) {
    // 成功：重置失败计数
    user.failCount = 0;
    user.lockedUntil = null;
    return { success: true, user: sanitizeUser(user) };
  }
  
  // 失败：增加计数并检查是否需要锁定
  user.failCount = (user.failCount || 0) + 1;
  if (user.failCount >= 5) {
    user.lockedUntil = new Date(Date.now() + 30 * 60 * 1000); // 30分钟
  }
  
  return { success: false, message: "用户名或密码错误" };
}
```

**幻灯片29：质量对比**
| 维度 | 小明版本 | 小华版本 |
|------|----------|----------|
| 密码安全 | ❌ 明文 | ✅ 加密 |
| 锁定机制 | ❌ 永久锁定 | ✅ 时间锁定 |
| 成功重置 | ❌ 未考虑 | ✅ 自动重置 |
| 并发安全 | ❌ 有风险 | ✅ 考虑周全 |
| 测试覆盖 | ❌ 不充分 | ✅ 全场景 |

### 秘密3：人机协作的艺术（10分钟）

**幻灯片30-31：对话模式的差异**

**小明与AI的对话**：
```
小明：帮我写个用户注册功能

```
（一次性交易，缺乏迭代）

**小华与AI的对话**：
```
小华：我需要实现用户注册，先帮我分析一下需要考虑哪些场景？
AI：需要考虑邮箱格式验证、密码强度、重复注册等...
小华：很好，请基于这些场景帮我设计测试用例
AI：[生成测试用例]
小华：测试用例不错，但我觉得还缺少并发注册的测试，请补充
AI：[补充测试]
小华：现在请基于完整的测试实现注册功能
AI：[生成实现代码]
小华：代码不错，但我看到有个地方可能有性能问题...
```
（持续对话，不断优化）

**幻灯片32-33：协作原则**

**小华的协作原则**：
1. **AI是助手，不是替代**：保持自己的思考和判断
2. **测试是合同，不是装饰**：用测试明确表达期望
3. **迭代是常态，不是失败**：通过多轮对话完善方案
4. **验证是必须，不是选择**：永远验证AI的输出

**关键洞察**：
> **测试用例 = 人机沟通的"合同"**
> - 明确了人类的期望
> - 给AI提供了精确的上下文
> - 创造了质量验证的标准

## 第三部分：AI时代软件开发的新范式（35分钟）

### 从个人手艺到人机协作（12分钟）

**幻灯片35-36：软件开发的历史演进**

**手工时代（1970s-1990s）**：
- 个人英雄主义
- 依赖经验和直觉
- 知识存在个人头脑中

**工程化时代（1990s-2010s）**：
- 流程化和标准化
- 团队协作和知识共享
- 工具和框架的普及

**AI协作时代（2020s+）**：
- 人机协作成为核心
- 智能化工具深度集成
- 认知负荷重新分配

**幻灯片37-38：核心转变对比**

```
传统模式：人 → 代码 → 系统
AI模式：人 ↔ AI → 代码 → 系统
```

**转变的本质**：
- 人的角色：从执行者变为设计师
- AI的角色：从工具变为伙伴
- 代码的属性：从手工艺品变为协作产品

**幻灯片39-40：价值重新定义**

**传统开发者价值**：
- 熟悉语法和API
- 快速编写代码
- 调试和修复问题

**AI时代开发者价值**：
- 理解业务和需求
- 设计架构和方案
- 质量把控和决策

**案例说明**：
- 小明困在传统价值观里：追求写代码快
- 小华抓住新价值观：追求方案好

### 从代码覆盖到风险洞察（12分钟）

**幻灯片41-42：传统测试的盲点**

**小明的测试观**：
- "我的代码覆盖率有85%，应该很安全了"
- 关注数字指标
- 平均分配测试资源

**现实的残酷真相**：
```
覆盖率100%的代码，仍然有30%的关键Bug未发现
```

**幻灯片43-44：小华的风险思维**

**小华的测试观**：
- "哪些代码最容易出问题？"
- "什么样的Bug影响最大？"
- "如何用最少的测试覆盖最多的风险？"

**风险驱动的测试策略**：
```
测试投入 ∝ 代码风险 × 业务影响
```

**幻灯片45-46：AI增强的风险识别**

**演示案例：电商系统风险分析**
1. **CodeScene分析**：识别出支付模块是"热点代码"
   - 复杂度高（圈复杂度15）
   - 修改频繁（近3月修改12次）
   - 业务关键（涉及资金）

2. **Claude深度分析**：
   ```
   支付模块存在以下风险：
   - 并发处理：多个订单同时支付可能导致重复扣款
   - 异常处理：第三方支付超时时的状态不一致
   - 数据一致性：支付成功但订单状态更新失败
   ```

3. **AI生成针对性测试**：
   - 并发支付测试
   - 超时重试测试
   - 状态一致性测试

**效果对比**：
- 小明方式：平均测试，80%覆盖率，仍有关键Bug
- 小华方式：风险聚焦，60%覆盖率，关键风险全覆盖

### 从纪律约束到即时心流（11分钟）

**幻灯片47-48：传统TDD的心理负担**

**小明的TDD体验**：

- AI自动生成测试骨架

**现场演示（5分钟）**：
**传统TDD vs AI增强TDD**

*场景：添加商品到购物车功能*

**传统方式演示**：
1. 创建test文件 → 30秒
2. 手写测试代码 → 90秒
3. 切换到src文件 → 10秒

**总计：325秒（5分25秒）**

**AI增强方式演示**：

2. Claude生成测试 → 5秒
3. AI生成实现 → 5秒
4. 自动运行测试 → 3秒
5. AI建议优化 → 10秒
**总计：33秒**

**幻灯片51-52：体验转变的本质**

**从"纪律"到"乐趣"**：

**从"负担"到"助力"**：

### 具体成长路径（12分钟）

**幻灯片56-58：路径A - 快速体验路径（适合小明阶段）**

**第4周：实战应用**

## 教学互动设计总览

### 互动环节统计
1. **自我对照**（3分钟）：学员判断自己像小明还是小华
2. **方法内化讨论**（3分钟）：讨论小华方法的关键点
3. **能力测试练习**（5分钟）：通过需求响应判断发展阶段
4. **现场演示观察**（5分钟）：对比传统和AI增强的TDD效率

### 情感曲线设计

**第一部分（认同感）**：
- 在小明身上看到自己 → 产生共鸣
- 小明的困境让人担忧 → 制造紧迫感

**第二部分（启发感）**：
- 小华的方法让人恍然大悟 → 产生洞察
- 具体对比让人信服 → 建立信心

**第三部分（系统感）**：
- 理解背后的原理 → 知识内化
- 看到发展趋势 → 战略思考

**第四部分（行动感）**：
- 明确个人路径 → 具体可行
- 获得工具资源 → 立即开始

### PPT制作和演讲建议

**视觉设计**：
- 用角色头像区分小明和小华的内容
- 对比表格要清晰醒目
- 代码示例字体要够大
- 时间线和流程图要直观

**演讲技巧**：
- 讲故事时要有情感投入
- 现场演示要确保流畅
- 观察学员反应，适时互动
- 结尾要有强烈的行动号召

**备用方案**：
- 准备离线版演示内容
- 提前测试所有工具和网络
- 准备纸质版关键资料

这个教学框架以故事对比为主线，通过强烈的情感冲击和具体的方法展示，帮助学员理解AI+TDD的价值并激发行动力，适合需要激发和感化的受众。
